# Сетевая тестовая версия

Эта сборка предназначена для ограниченного испытания на Windows 10/11 x64 из общей сетевой папки.

## Реализовано

- запуск `production-cycle.exe` из общей папки с автоматическим копированием EXE, frontend и Fixed WebView2 в локальный профиль Windows;
- общий проверяемый снимок базы без прямого открытия SQLite по SMB;
- не более трёх одновременно работающих компьютеров;
- вход по существующему профилю и PIN;
- отказ четвёртому обычному пользователю;
- приоритетный вход администратора с кооперативным вытеснением последнего вошедшего обычного пользователя;
- автоматический черновик после изменения и перед вытеснением;
- сохранение прежней процедуры подписанного сохранения, обязательного комментария, журнала и резервных копий;
- отсутствие собственных `.log`, службы, автозапуска и установки WebView2.

## Как испытывать

1. Сделайте резервную копию текущей папки программы и базы.
2. Полностью распакуйте `ProductionCycleNetwork` в отдельную общую папку.
3. Дайте тестовым пользователям права чтения и записи в эту папку.
4. На каждом компьютере запускайте корневой `production-cycle.exe`.
5. Проверьте последовательный вход трёх пользователей, отказ четвёртому и приоритетный вход администратора.

Стабильную однопользовательскую папку не заменяйте этой сборкой. До промышленного использования нужны физические испытания на вашей SMB-папке, Windows 10 и Windows 11, включая обрыв сети и аварийное завершение процесса.

## Исправление первого запуска (05.10.2026)

Отсутствующий ID при первичной настройке больше не преобразуется в 0. На пустой
базе сразу открывается форма создания единственного администратора. После создания
профиля временная сессия привязывается к нему. При ошибке чтения общей папки
доступна кнопка «Повторить».

Windows-проверка теперь выполняет действия в реальном UI упакованного приложения,
с реальными IPC и SQLite, а не создаёт первого пользователя в обход формы.
Отдельный повторный запуск проверяет сохранение профилей и проектов и вход по PIN.
Сетевые тесты проверяют лимит трёх сессий и сохранение черновика до вытеснения
последнего пользователя администратором. Физическая печать и реальная SMB-сеть
остаются отдельной приёмкой на целевых компьютерах.

## Исправление запуска без окна

- Нативное окно подготовки при получении локальной копии с сервера.
- Видимые сообщения об ошибках до запуска WebView2 и таймаут готовности интерфейса.
- Проверка локального диска для runtime и профиля, включая перенаправленные профили.
- Блокировка одновременной подготовки кэша и проверка обязательных файлов кэша.
- Реальный SMB-тест через loopback IP: первое открытие, повторный запуск, сетевой диск,
  перенаправленный профиль, обычное видимое окно и ошибка конфигурации.
- Две среды CI: Windows Server 2022/2025. Windows Server 2019 требует отдельной приёмки.
- Функции проекта и шрифты печатных форм сохранены.

## Формальная терминология и учёт сеансов (15.10.2026)

- В формах, подсказках, подтверждениях, ошибках и новых записях журнала применяются термины «головной этап», «зависимый этап», «основной проект» и «срок исполнения». Ранее подписанные записи журнала не переписываются; их старые обозначения полей показываются с новой терминологией без изменения данных и подписей.
- В печатном отчёте явно различаются основной проект и головной этап. Шрифты и размеры печатных форм сохранены.
- Счётчик «Сетевые сеансы» показывает фактически занятые слоты, а не накопившиеся JSON-файлы. При обычном выходе слот освобождается явно. После аварийного завершения оставшиеся записи очищаются при следующей проверке освобождённого слота.
- Работающий сеанс не удаляется только из-за старой отметки времени. При обрыве соединения освобождение слота зависит от снятия SMB-блокировки сервером.
- Проверки включают два экземпляра готового EXE через SMB, переход счётчика 1 → 2 → 1, штатное закрытие, принудительное завершение, повторный вход, лимит трёх мест и приоритет администратора.

### Обновление существующей сетевой папки

1. Закройте все экземпляры программы на сервере и рабочих компьютерах.
2. Сделайте резервную копию всей текущей папки.
3. Распакуйте новый архив в отдельную папку. Перенесите в неё каталог `shared` из прежней сетевой версии, сохранив базу, подписи, журнал, черновики и резервные копии. Старые файлы сеансов в `shared/sessions` программа проверит автоматически.
4. Откройте новый корневой `production-cycle.exe` из общей папки. При первом запуске новой версии локальная копия обновится автоматически.

Формат базы и обменных TXT не изменён. Испытания на конкретном Windows Server 2019 и физических рабочих компьютерах остаются отдельной приёмкой.
