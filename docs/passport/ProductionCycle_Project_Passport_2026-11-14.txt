Паспорт проекта Производственный цикл

Версия паспорта 1.0 от 14 ноября 2026 года. Документ предназначен владельцу проекта и разработчику для сопровождения программы и продолжения работы в новом чате.

Действующее решение: отдельное окно Windows EXE с включённым в поставку Fixed WebView2. Для совместной работы EXE запускают ярлыком из общей папки; исполняемая часть автоматически подготавливается на локальном диске сотрудника, общие данные остаются на сервере. [S1, S2, S3]

Попытка использовать серверную программу с открытием через Edge и Internet Explorer завершилась возвратом к настольному приложению. Изменения интерфейса и функций, сделанные в браузерной версии, были перенесены в локальную основу. История перехода и отката приведена отдельно в разделах 3–5. [U1–U6, S13, R3]

1 Назначение и обязательные требования

Программа ведёт производственный проект и связанные этапы, показывает подчинённость, исполнителей, сроки и состояние выполнения. Руководитель видит рабочий реестр, общий контроль сроков и диаграмму Ганта; изменения подтверждаются персональным профилем и PIN. [S7, S8, S10]

Функциональная основа

- Карточка проекта и иерархия этапов. У одного заказа может быть несколько самостоятельных проектов; номер заказа не заменяет идентификатор проекта.
- Реестр с фильтром выполнения, сворачиваемая структура подчинённости, контроль сроков и Гант с масштабами день, неделя, месяц и квартал.
- Поиск сохранённых проектов, создание и копирование этапов, импорт проекта из утверждённой книги Excel, скачивание её образца.
- Профили пользователей, единственный администратор, подписанное сохранение, журнал изменений, проверка целостности и резервные копии.
- Печать отчёта проекта, структуры подчинённости и Ганта на A3/A4. Выполненные этапы сохраняются в базе и учитываются в отчётности.

Условия эксплуатации

Поставка должна оставаться автономным ZIP для Windows x64 с EXE в корне. Для штатной работы не требуется устанавливать Python, Node.js, Rust или отдельно загружать WebView2, шрифты и значки. Ресурсы приложения находятся внутри комплекта; интернет в рабочем контуре отсутствует. [S1, S12, S15]

Обычный запуск выполняется без повышения прав. При сетевой работе сотруднику необходимы чтение и запуск файлов комплекта, запись в shared и доступная для записи локальная папка. Настройка прав общей папки относится к Windows и выполняется отдельно. [S1, S3, S4]

Принтер и его драйвер должны уже работать в Windows. ZIP содержит ресурсы приложения, но не драйверы всех возможных принтеров. Для получения PDF через системное окно нужен уже доступный PDF-принтер. [S16]

Собственные технические логи по умолчанию отключены. Подписанный деловой журнал и резервные копии сохраняются, поскольку это функции программы. Отсутствие всех следов в Windows не обещается. [S10, S15]

2 Варианты запуска и принятая схема

В истории проекта использовались три разные схемы. Их необходимо различать при обновлении, переносе данных и диагностике. Слово «локальная» относится к месту исполнения программы; общие данные при этом могут храниться на сервере. [S1–S3, S13, S16]

Схема | Где работает интерфейс | Где находятся данные
Самостоятельная локальная | EXE и встроенный WebView2 на локальном диске | data рядом с этой копией программы
Нативная через общую папку / Текущий итоговый ZIP | Ярлык указывает на общий EXE; клиент и WebView2 работают из локального кэша | Общий снимок в shared сервера; рабочая SQLite клиента локальна
Серверная через браузер / Историческая попытка | Установленный Edge или IE11 открывает HTTPS-страницу | SQLite обслуживает серверный процесс

Принятое решение

Сотрудник открывает папку сервера или ярлык на production-cycle.exe. Программа подготавливает локальную исполняемую копию и открывает собственное окно. Выдавать пользователю URL, запускать серверную консоль, создавать службу приложения и устанавливать доверие HTTPS-сертификату для этого комплекта не требуется. [S1–S4]

Встроенный WebView2 отображает HTML и JavaScript внутри приложения. Он поставляется вместе с программой и не равнозначен запуску через установленный Internet Explorer. Внутренний адрес production://localhost не означает отдельный HTTP-сервер на порту 8443. [S2, S6, M1]

Сетевая папка и RDP

Доступ к файлам SMB и удалённый рабочий стол RDP — самостоятельные способы доступа. Возможность открыть общую папку не подтверждает наличие RDP; работающий RDP также не доказывает доступность HTTPS-сервера. Для текущего запуска с рабочего стола требуется SMB и разрешённый локальный запуск клиента. [S1, S13]

Если программу открывают внутри уже настроенного RDP-сеанса, исполняться она будет на том компьютере, к которому подключились. Это иной сценарий, чем запуск ярлыка сетевого EXE на рабочем компьютере сотрудника. [S16]

4 Неудачная попытка браузерной архитектуры

Попытка была предпринята, чтобы упростить открытие программы и совместный доступ: единая программа на сервере, работа сотрудников через Edge, для старых систем — Internet Explorer. Требовалось сохранить интерфейс и пользовательские функции, обеспечить автономность и простой запуск. [U1, U2, S13]

Серверный комплект предусматривал HTTPS на порту 8443, собственный серверный EXE, настройки подключения, сертификаты и возможность постоянного запуска. Вариант входа из общей папки открывал браузер сотрудника, а не переносил на него серверный процесс. [S13]

Ошибка доступа | Отказ при создании общей папки базы; код ОС 5. Позднее пользователь указал на размещение в личном профиле | Права Windows требовали отдельного исправления
Сложное открытие | По двойному нажатию появлялась консоль с https://localhost:8443; требовался максимально простой вход | Запущенный сервер не воспринимался как готовое рабочее окно
Разная вёрстка | В удалённом Edge отображение было корректным; в IE подписи и кнопки смещались | Пришлось поддерживать отдельную совместимость IE

По сообщениям пользователя отдельные открытия и сценарии Edge работали. Поэтому итог истории: браузерный путь оказался неудачным для выбранных условий эксплуатации и был отклонён владельцем; утверждение о полной неработоспособности любой серверной версии было бы неверным. [U3–U6]

Открытие через браузер не заменяет права Windows на серверную папку и базу. Сам факт размещения на диске C также не подтверждает доступ сотрудников: необходима проверка разрешений для их учётных записей. [U1, U6, S13]

5 Откат и сохранение накопленных изменений

Решение владельца: «мне нужен откат до последней локально работающей версии, не серверной»; при этом требовалось применить изменения, внесённые за время работы над серверной версией. Это зафиксированный выбор архитектуры, а не отказ от новых функций. [U6]

Первый этап возврата

Восстановлена самостоятельная локальная поставка с EXE и встроенным WebView2. Она открывает обычное окно без серверной службы и хранит собственную базу в data. Код локальной основы закреплён коммитом 3226084. Инструкция этой поставки прямо предупреждает, что независимые копии на разных ПК имеют разные базы. [R3, S16]

Второй этап возврата

После сообщения о зависании ярлыка восстановлен штатный механизм общей папки для нативного клиента. EXE, WebView2, профиль и рабочая SQLite должны быть локальными; общей остаётся публикация данных в shared. В коде устранён обход сетевой подготовки в режиме local-desktop. [R2, S2–S6]

Что было сохранено

- Интерфейс рабочих вкладок и отдельный административный раздел; профили, персональные PIN, журнал и резервные копии.
- Поиск проектов на главном экране и прокручиваемый список сохранённых проектов.
- Копирование однотипных этапов, фильтры выполненных этапов и сохранённая структура подчинённости.
- Импорт утверждённого Excel, образец для всех пользователей, ограничение кнопки экспорта в Реестр ролью администратора.
- Правила при первом входе профиля, повторный вызов через «Ещё» → «Подсказки».
- Отчёт проекта, печать структуры и Ганта A3/A4, исправления пустой первой страницы и переносов текста.

В текущем комплекте браузерные исправления IE сохраняют значение как история и источник требований. Рабочее окно и печать текущей версии обслуживает встроенный WebView2. Наличие server и legacy в репозитории само по себе не означает включение браузерной архитектуры в финальную поставку: упаковщик удаляет frontend/legacy. [S2, S11, S12]

6 Текущая архитектура и запуск

Фактический стек выпущенного клиента: Rust, Tauri 2, SQLite через rusqlite, включённый Fixed WebView2; интерфейс состоит из HTML, CSS и JavaScript. React/Vite указан в исходных целевых требованиях, но действующий frontend этой сборки нельзя описывать как React-приложение. [S2, S7, S8, S14, S15]

Последовательность открытия

1. Ярлык или Проводник запускает production-cycle.exe из полной общей папки. Пути определяются от EXE, а не от рабочей папки ярлыка.
2. Нативное окно подготовки проверяет config/network.json, общую папку и launch-manifest.json.
3. Выбирается доступная папка на настоящем локальном диске. Сетевое перенаправление профиля и сетевые диски не принимаются как локальный кэш.
4. Исполняемые файлы копируются и проверяются по размеру и SHA256. Неполный или повреждённый кэш не признаётся готовым.
5. Локальный дочерний процесс получает адрес общего хранилища и отдельные локальные каталоги профиля и рабочей базы.
6. Открывается SQLite на локальном диске; под контролем блокировок читается общий снимок. Рабочее окно показывается после сигнала готовности интерфейса.

Почему требуется локальная копия

Microsoft указывает, что Fixed Version WebView2 нельзя запускать с сетевого или UNC-пути, и рекомендует не размещать его пользовательский профиль на общей папке. Локальная подготовка встроенного движка является частью рабочего запуска. [M1, M2]

Кандидаты кэша проверяются по очереди: LOCALAPPDATA, AppData/Local внутри профиля пользователя и временная папка Windows. Программа проверяет создание, запись, блокировку, переименование и удаление пробного файла. При неудаче используется следующий допустимый локальный путь. [S4]

Процесс на сервере для координации не нужен. Сервер предоставляет файлы через SMB; интерфейс общается с нативными командами через IPC Tauri. В штатном режиме не открывается отладочный порт: CDP включается только тестовым сценарием. [S2, S3, T3]

7 Данные и совместная работа

В режиме общей папки серверный файл является согласованным снимком данных. SQLite-соединение каждого клиента открывается на локальном диске. Прямое совместное открытие SQLite по SMB запрещено требованиями проекта и не используется действующим транспортом. [S3, S15]

Расположение | Назначение
production-cycle.exe | Точка запуска комплекта
frontend и runtime/webview2 | Интерфейс и встроенный движок; копируются в локальный кэш
config/network.json | Включение общей папки, версия комплекта, предел сеансов
launch-manifest.json | Список неизменяемых файлов, размеров и SHA256
shared/database/production-cycle.db | Общий согласованный снимок базы
shared/sessions и shared/control | Допуск сеансов и координация
shared/drafts и shared/backups | Черновики и резервные копии общего режима
Локальные data и temp клиента | Рабочая SQLite, профиль WebView2 и временные данные
Локальная папка восстановления | Непереданные изменения; размещена вне версии кэша

Перед чтением и записью клиент берёт блокировку общего хранилища и обновляет локальную базу из актуального снимка. После успешной операции публикуется новый снимок. Проверка ревизии проекта предотвращает безусловное сохранение поверх изменённой версии. [S3, S10]

При срыве публикации программа сообщает, что общая запись не подтверждена, и сохраняет локальную копию для ручного восстановления. Автоматическое повторное применение такой базы не выполняется. Черновик и локальная копия не равны подтверждённому общему сохранению. [S3]

Допускаются три активных сеанса. Администратор может освободить место через предусмотренный механизм вытеснения обычного пользователя с сохранением черновика. Выход и завершение приложения освобождают допуск. [S3, T1]

Если ранее инициализированный общий снимок исчез, программа останавливает операцию и требует восстановления. Она не должна создавать новую пустую базу вместо потерянной. [S3]

В программе действуют роли «Руководитель проекта», «Проверяющий» и «Администратор». Администратор создаётся при первичной настройке в единственном экземпляре; у рабочих пользователей собственные профили и PIN. Минимальная длина PIN в текущем backend — 6 символов. [S7, S10]

Подпись и деловой журнал

Изменения базы записываются через подписанное сохранение с выбором пользователя, PIN и обязательным комментарием. Журнал фиксирует различия «было → стало». Для завершения этапов требуются реквизиты существующего документа и комментарий; скан в этом окне не загружается. [S10, S16]

Ключи и проверка событий реализованы внутри программы; используются Argon2, шифрование ключа и Ed25519. Не следует называть эту внутреннюю подпись внешним сертификатом организации. Перенос только JSON проекта не переносит полную историю, профили и ключи. [S10]

Уточнение для дальнейшей разработки

В действующем коде AnySigner включает все три роли, и этот допуск используется при сохранении с завершением этапов. Если проверяющему необходимо оставить только контроль без права завершения, это отдельная будущая правка разрешений backend и её тестов. При подготовке паспорта поведение не изменялось. [S10]

9 Интерфейс поиск и копирование этапов

Основной экран

Сохранены вкладки «Реестр цикла», «Контроль сроков» и «Диаграмма Ганта». Административные действия вынесены в отдельный интерфейс. Поле «поиск проектов» находится на главном экране и позволяет искать по названию, номеру заказа или предприятию. После «Найти» открывается прокручиваемый список найденных проектов; отдельная поисковая строка из этого списка убрана. [S7, S16]

В меню «Ещё» находятся импорт проекта, скачивание образца, подсказки и печать отчёта. Кнопка «Экспорт для Реестра» показывается администратору. Правила появляются при первом входе конкретного профиля; повторно их можно открыть через «Подсказки». [S6, S7]

Копирование однотипного этапа

1. В реестре найти исходный этап и нажать «Копировать» в его строке. Если он выполнен, выбрать «Все этапы» или «Только выполненные».
2. Программа открывает форму новой копии на том же уровне подчинённости. Переносятся название с пометкой «копия», исполнитель, адресаты, даты и комментарий.
3. Статус новой записи становится «Не начато», а идентификатор создаётся заново. Изменить нужные поля и сохранить этап.
4. Подписать и сохранить проект, чтобы изменения попали в базу.

Подчинённая ветка, документ о выполнении и прежняя подпись при копировании не переносятся. Копирование предназначено для ускорения повторяющегося производства и не подтверждает выполнение новой работы. Сценарий проверен для всех трёх ролей в нативном окне. [S7, S16, T1, T3]

Скрытые выполненные этапы

По умолчанию рабочий список скрывает выполненные этапы. Они продолжают существовать в проекте и входят в общий процент выполнения и печатный отчёт. Фильтр рабочего экрана не должен уменьшать фактический объём проекта. [S8, S11, S16]

У этапа один головной элемент; циклическая подчинённость недопустима. Для ритмичных работ следует создавать новые копии, а не многократно переиспользовать один выполненный этап с прежним подтверждением. [S7, S8, S10]

10 Импорт Excel и выдача образца

Импорт использует утверждённый формат .xlsx. Операция читает книгу и показывает предпросмотр; внесение проекта в базу по-прежнему требует подписанного сохранения. Импорт не создаёт подписи за сотрудников и не подтверждает выполнение этапов. [S9, S16]

Лист | Поля утверждённого формата
Проект | Номер заказа; наименование проекта; инициатор; исполнитель; предприятие; начало; срок исполнения
Этапы | Код этапа; код головного этапа; наименование этапа; исполнитель; адресаты; начало; срок исполнения; комментарий

Рабочий порядок

1. Открыть «Ещё» → «Скачать образец отчёта». Программа сохраняет файл в локальную папку exports и показывает полный путь.
2. Заполнить копию образца. Заголовки и структуру листов сохранить. Указать коды для восстановления подчинённости этапов.
3. Выбрать .xlsx через «Импорт проекта», проверить строки и предупреждения в предпросмотре, подтвердить импорт.
4. Проверить карточку, этапы и сроки; подписать сохранение проекта своим профилем и PIN.

Ограничения текущего импортера

Размер файла ограничен 5 МиБ: в коде это 5 × 1024 × 1024 байт. Формулы нужно заменить значениями. Макросы, внешние ссылки и защищённые архивы не поддерживаются; структура ZIP и размеры листов проверяются до разбора. Excel на компьютере не нужен для чтения файла самой программой, но требуется подходящий редактор для заполнения книги. [S9]

Исправление скачивания

Историческая браузерная ошибка связывала получение образца с неизвестной или запрещённой серверной операцией. В нативной версии команда save_excel_template выдаёт встроенные байты книги напрямую в файл. Образец доступен всем ролям; уже существующий файл не затирается, для следующей копии добавляется номер. [U4, S6]

Сам образец также находится в samples. В испытании скачанного через IPC файла сравнивается SHA256 с утверждённой книгой. Изменение листов или заголовков требует отдельного согласования формата и изменения импортера. [S9, S12, T3]

11 Печать и сохранённые исправления отчётов

Печатные функции доступны из рабочего интерфейса: «Ещё» → «Печать отчёта / PDF», кнопка «Печать структуры» и отдельные кнопки Ганта «Печать А3» и «Печать А4». В текущей версии вызов системной печати идёт через нативную команду print_report; Internet Explorer не используется. [S7, S11, S16]

Исторические дефекты

В браузерных версиях пользователь сообщал о пустой первой странице, отсутствии реакции кнопок Ганта и распавшемся отчёте IE. На снимках сведения о проекте вытягивались в одну колонку, а даты, статус и оставшийся срок перекрывали соседние ячейки. Эти наблюдения являются причиной требований к нынешней печати. [U3, U5, S13]

Что закреплено в текущем варианте

- Сведения о проекте и показатели имеют табличную печатную компоновку; первая страница включает начало списка этапов.
- Колонки этапов имеют заданные доли ширины, длинные слова и даты переносятся в своих ячейках.
- Сохранён основной размер текста отчёта около 14 пунктов; автоматическая проверка контролирует размер дат, выход за лист и перекрытие слов.
- Отчёт учитывает все этапы независимо от рабочего фильтра. Предусмотрены многостраничные проекты.
- Ошибки подготовки или вызова печати показываются в интерфейсе. Сообщение после подготовки указывает на Ctrl+P как доступное повторное действие.

Семь проверенных вариантов

Автоматически сформированы PDF из окна поставленного Fixed WebView2: отчёт на 9 этапов в двух ориентациях A4; отчёт на 45 этапов в двух ориентациях A4; Гант A3; Гант A4; структура подчинённости. Итого 2 + 2 + 1 + 1 + 1 = 7 вариантов. Для каждого проверено отсутствие пустых страниц. [T1, T3]

Проверка компоновки использует PDF-вывод движка; открытие системной печати проверяется отдельно нативным сценарием. Испытания не подтверждают печать на конкретном физическом принтере пользователя. Перед рабочей выдачей следует проверить бумагу, ориентацию и масштаб в уже установленном драйвере. [T1, T3, S16]

Сроки и просрочка рассчитываются относительно системной даты устройства. Корректные часы рабочих компьютеров важны для одинаковой интерпретации отчётов. [S7, S8]

12 Зависание ярлыка и диагностика запуска

После отката пользователь сообщил: на сервере программа запускается, а с рабочего стола через ярлык зависает на этапе «Открытие окна программы…» и показывает белое окно. Пользователь потребовал вернуть уведомление, указывающее точное место остановки. [U7]

Исправления в EXE 0c7663b

- Сетевая подготовка больше не обходится из-за режима local-desktop. Дочерний клиент сохраняет адрес общего хранилища и локальные рабочие пути.
- До WebView проверяются обязательные файлы frontend, доступность runtime и локальность каталога профиля и SQLite.
- Главное окно скрыто до готовности интерфейса. Ошибки ресурсов, JavaScript и асинхронных операций передаются в нативную диагностику.
- Окно подготовки показывает этап, прошедшее время, пути, причину и код ОС при наличии. Текст ошибки можно выделить и скопировать.
- Ожидание отдельного этапа создания и загрузки окна ограничено 45 секундами; у общей подготовки есть предел 300 секунд. Родительский загрузчик также контролирует дочерний процесс.
- При неудаче проверяется следующий разрешённый локальный каталог; отмена запуска останавливает подготовку. [S2–S6]

Оставшийся CMD дефект

После основной починки обнаружен отдельный сбой вспомогательного app/start.cmd: он менял текущую папку через cd /d, что не обеспечивало работу из UNC. В финальном коммите d12e437 проверки и запуск переведены на полные пути от %~dp0. Основной вход остаётся двойным нажатием на EXE. [R1, S12, T2]

Если проблема повторилась

1. Сохранить текст или снимок нового окна диагностики. Зафиксировать название ZIP, этап, путь EXE и код ошибки.
2. Убедиться, что ярлык указывает на EXE нового полностью распакованного комплекта, а не на старую папку.
3. Проверить доступ пользователя к shared и доступную локальную папку; не удалять базу или очереди восстановления ради запуска.
4. При необходимости запустить app/diagnose-startup.cmd: это явное включение отдельного отчёта, а не постоянно работающий логгер.

Исправление механизма проверено в Windows CI. Конкретная причина каждого отказа корпоративного рабочего места определяется его диагностикой; работоспособность этой машины нельзя выводить только из успешного запуска на сервере. [S1, S4, T1]

13 Обновление перенос базы и возврат версии

Перед переносом

Нужно завершить работу пользователей, создать проверенную резервную копию и сохранить старую папку целиком. Новый ZIP распаковывается полностью в новую папку. Перенос приложения поверх работающего комплекта и смешивание файлов разных архитектур не применяется. [S1, S16]

Источник данных | Перенос в новый комплект
Прежний нативный общий режим | Перенести папку shared целиком
Самостоятельная локальная версия | Перенести папку data целиком
Серверная версия с браузером | Взять проверенную полную резервную копию .db, поместить в data под именем production-cycle.db

При наличии shared/database/production-cycle.db именно этот общий снимок является основным. data/production-cycle.db используется для первоначального переноса только при отсутствии общей базы. Не следует подменять общий снимок новой локальной базой. [S1, S3]

Контроль после открытия

1. Создать новый ярлык на EXE нового комплекта и открыть его с рабочего места обычного пользователя.
2. Войти прежним профилем и PIN. Проверить список проектов, этапы, пользователей и деловой журнал.
3. Создать резервную копию через административный раздел. Не создавать заново пользователей вместо переноса полной базы.
4. Проверить один проект из второго сеанса: данные и подписи должны сохраняться. После выхода место должно освобождаться.

Если нужно вернуться к прежнему выпуску

Предпочтительный возврат после неудачного обновления: закрыть новую программу и использовать сохранённый старый комплект с его согласованной базой. Подменять только EXE и оставлять неизвестно совместимые frontend, config или runtime нельзя. Если в новой версии уже внесены данные, сначала сохранить её полную базу и отдельно решить перенос изменений. [S1, S16]

Очереди восстановления

Непереданная локальная база и черновик требуют разбора по сообщению программы. Их нельзя автоматически считать общими сохранёнными данными или без проверки накатывать поверх актуального снимка. Механизм кэша сохраняет данные восстановления отдельно от каталога конкретной версии. [S3, S4]

16 Продолжение проекта и нерешённые вопросы

Первый следующий этап

1. Открыть итоговый ZIP целиком из новой общей папки через новый ярлык обычного сотрудника. Подтвердить появление рабочего окна без повышения прав.
2. Проверить перенесённые профили, PIN, проекты и журнал. Сохранить резервную копию.
3. Выполнить контрольный поиск, скачивание образца, импорт тестового проекта и копирование этапа. Проверить сохранение со второго сеанса.
4. Выполнить печать отчёта, структуры и Ганта на фактически установленном принтере или PDF-принтере. Сверить первую страницу и длинные подписи.
5. При отказе передать новое окно диагностики. Использовать конкретный этап и код ошибки как основание следующего исправления.

Отдельные решения при следующих изменениях

- Роль проверяющего. Текущий backend допускает его подписанное завершение этапов. При необходимости сузить полномочия изменение должно затрагивать backend, UI и тесты разрешений. [S10]
- Полная инструкция. Для текущей общей папки основной документ запуска находится в ZIP; самостоятельную локальную инструкцию нужно адаптировать перед использованием как сетевой. [S1, S16]
- Обновления автономного runtime. Приложение использует включённую фиксированную версию. При её замене нужен новый проверенный полный комплект и обновлённый манифест. [S4, S12, M1]
- Защита файлов. Роли программы и PIN не заменяют SMB/NTFS-разрешения и организацию резервных копий. SHA256 манифеста проверяет соответствие комплекту; его нельзя считать внешней подписью издателя. [S3, S4, S10]

Правила передачи в новый чат

Передать этот паспорт и ссылку на итоговый ZIP. Начать с разделов 2, 5, 12 и 15. Зафиксировать, какие проверки уже выполнены на реальном рабочем месте после выпуска. При новой ошибке приложить точный текст диагностики, а не только сообщение «не запускается».

Продолжать от зафиксированного нативного кода. Сохранять утверждённый интерфейс, импорт и образец Excel, подписи и общую базу. Возврат к серверу с браузером является отдельным изменением архитектуры и требует нового прямого решения владельца.
