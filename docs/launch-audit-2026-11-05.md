# Аудит запуска из общей папки

Объём: действующая сетевая поставка Windows 10/11 x64. Пользователь открывает
`production-cycle.exe` из общей папки на своём компьютере; рабочее окно должно
появиться в его интерактивном сеансе. Отдельная версия Windows 7 не создаётся.
Исходная база изменений — сетевая ветка после объединения PR #6 (`1e3ebc1`).

## Выявленные причины и изменения

| Проблема в коде | Исправление |
|---|---|
| `is_file()` скрывал ошибки доступа к сетевой конфигурации; отсутствие файла включало обычный режим | Ошибка проверки содержит путь; сетевая папка или сетевой комплект без включённого `network.json` не запускаются как standalone |
| Готовность кэша определялась наличием нескольких файлов | Поставка содержит манифест SHA-256; локальные файлы проверяются перед использованием |
| При обновлении удалялся прежний каталог версии | Повреждённый кэш восстанавливается рядом; старые EXE, данные и очереди не удаляются |
| Один старый `prepare.lock` блокировал новые запуски | Подготовка разделена по идентификатору общей папки; ожидание ограничено и содержит путь |
| Проверялась только простая запись в локальную папку | Проверяются запись, синхронизация, блокировка, переименование и удаление собственного пробного файла |
| Локальная запись не доказывала возможность запуска EXE | При неудаче подготовки или запуска клиента проверяется следующий доступный локальный путь; общая база и папка восстановления сохраняют привязку |
| Загрузчик завершался сразу после `spawn` | Он ждёт подтверждения видимого окна и `frontend_ready` от конкретного PID; ранний выход и тайм-аут видны пользователю |
| Отказ вспомогательного `icacls` безусловно прекращал запуск | Используется системный путь утилиты; после её отказа проверяется фактическое создание WebView2, а подробность настройки прав включается в ошибку окна |
| Часть файловых ошибок не содержала операции и пути | Добавлены контекст этапа, операция, путь и код ОС; сохранён исходный текст ошибки |
| Профиль WebView2 мог зависеть от внешнего окружения | Клиент явно задаёт локальную папку профиля через WebView2 builder и переменную окружения |

Код 5 сам по себе не устанавливает причину конкретного происшествия на сервере
пользователя. Исходный текст, путь и политики того компьютера не воспроизведены.
Изменения устраняют выявленные ошибки запуска и добавляют проверяемые сценарии.

## Автоматизированная проверка

`scripts/test-network-portable.ps1` использует настоящий SMB через TCP/IP
(`\\127.0.0.1\…`), а не подмену общей папки локальным файловым путём.

- Холодный и повторный запуск; подключённый сетевой диск.
- Запуск под отдельной стандартной учётной записью без членства Administrators,
  с загрузкой её профиля Windows; сам стенд использует административные права
  для подготовки SMB и изолированных тестовых разрешений.
- Перенаправленный сетевой профиль с разрешённым локальным TEMP.
- Повреждённая локальная HTML-копия и открытый без разрешения удаления EXE:
  создаётся новый клиент, прежние файлы остаются.
- Настоящий NTFS-отказ создания файла в `shared/drafts`: видимая ошибка с кодом 5,
  путь и операция; общая база до и после не меняется.
- Настоящий отказ чтения исходного frontend при пустом кэше: понятная ошибка.
- Настоящий отказ исполнения локального EXE: переход к другому локальному пути
  с последующим открытием рабочего окна.
- Запрещённая запись в основной профиль: разрешённый локальный TEMP используется
  автоматически.
- Запрещены все локальные каталоги: видимый отказ с путями и кодом 5; файлы
  исходной поставки с атрибутом только для чтения корректно копируются локально.
- Отсутствующий и повреждённый `network.json`: понятный отказ вместо скрытого
  переключения на другой режим.
- Обычный запуск без self-test: видимое главное окно.
- Функциональные проверки UI/IPC, подписанных сохранений, завершения этапов,
  резервного копирования, восстановления и выхода; два одновременно работающих
  клиента, штатное закрытие и принудительное завершение.
- Rust-тесты проверяют выход за границы манифеста, дубликаты, повреждение исходной
  поставки, восстановление кэша без удаления прежних данных и контекст ошибок.

Результат каждого CI-запуска определяется фактическими job/step и JSON-отчётами
артефакта `production-cycle-network-evidence-*`. В отчёте запуска `state=ready`
означает подтверждённое видимое окно, а не просто наличие процесса.

CI выполняется на Windows Server 2022 и 2025. Это не приёмка на физической
Windows 10/11, Windows Server 2019, двух отдельных ПК или сервере пользователя.
Проверка настоящего RDP-сеанса и корпоративных AppLocker/WDAC/EDR остаётся
отдельной эксплуатационной приёмкой. Политики защиты и sandbox не отключаются,
повышение прав не запрашивается, системные журналы не удаляются.

## Эксплуатация

В корне ZIP остаётся EXE. Сетевые данные находятся в `shared`; исполняемые
компоненты, SQLite рабочей копии и профили WebView2 используются локально.
Вызов `app/diagnose-startup.cmd` по запросу пользователя сохраняет JSON-отчёт
с путями и результатом запуска в TEMP. PIN и содержимое проектов не включаются.
По умолчанию постоянный технический журнал не создаётся.

Перед обновлением закрыть клиентские окна и сохранить резервную копию `shared`.
Обновлять комплект целиком вместе с `launch-manifest.json`, сохраняя рабочую
папку `shared`; не подменять её пустой папкой из нового ZIP. После обновления
проверить открытие существующего проекта с отдельного клиентского компьютера.
Не переносить весь рабочий комплект в другой каталог для обхода отказа: такая
копия может стать отдельным источником данных.
