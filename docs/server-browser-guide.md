# Производственный цикл простой автономный запуск

Полная пошаговая инструкция: **ProductionCycle_Setup_Guide.docx**.
Без Word откройте **ProductionCycle_Setup_Guide.html** в Edge. Обе инструкции
включены в ZIP и не требуют интернета.

## Проверка на своём компьютере

1. Распакуйте ZIP целиком в новую локальную папку с правом записи.
2. Дважды нажмите **Производственный_цикл.exe**.
3. Программа дождётся готовности сервера и откроет отдельное окно Edge.
   Новая копия доступна только на этом ПК: **http://127.0.0.1:8080**.
4. Создайте администратора и тестовый проект. Сохраните его и проверьте печать.

Повторный щелчок открывает уже работающую копию. Закрытие браузера не останавливает
сервер. Для завершения ручного запуска используйте **Остановить_программу.cmd**.
Ошибки обычного запуска выводятся в отдельном окне Windows.

## Общий сервер

На постоянном сервере откройте **Настроить_сервер.cmd**. Однократно нужны права
администратора Windows. Мастер просит подтвердить остановку, указать постоянный
IP/имя сервера и разрешённые адреса сотрудников. Enter означает только LocalSubnet.
Для другой площадки адреса и маршрутизацию согласуют с ИТ.

Мастер настраивает HTTPS 8443, правило брандмауэра Domain/Private, автоматическую
службу LocalService и создаёт **Подключение_сотрудника.zip**. Первый администратор
создаётся на сервере по локальному адресу. Служба работает независимо от RDP
и запускается после загрузки Windows.

Сотруднику передаётся только комплект подключения. После распаковки он запускает
**Подключить.cmd**, сверяет SHA256 сертификата с администратором и подтверждает
доверие для текущего пользователя. Создаётся ярлык на рабочем столе, открывающий
отдельное окно Edge. При отсутствии Edge используется установленный IE11.
База, PIN и закрытый ключ в комплект подключения не включаются.

Для удалённой площадки нужен существующий корпоративный канал и разрешённый TCP
8443. Если разрешён только RDP, браузер открывают внутри удалённого рабочего стола.
Доступ к общей папке сам по себе не даёт доступ к работающему приложению.

## Перенос и обновление

Сначала закройте старые клиенты и сохраните резервную копию. В новой распакованной
папке **до первого запуска** выполните **Перенести_старую_базу.cmd** и выберите
действующую production-cycle.db. Исходник не изменяется, существующая новая база
не перезаписывается. Старые черновики и резервные копии сохраните отдельно.

Для обновления завершите сеансы, остановите сервер и сохраните **server-data,
config, tls, server.cer**. Обновляются EXE, frontend, scripts и инструкции;
рабочие данные и настройки сохраняются. Не работайте с разными копиями базы параллельно.

## Автономность и требования

Интернет для работы и настройки не нужен. EXE содержит SQLite и статический CRT.
Шрифты, значки, интерфейс и IE11-совместимые скрипты включены в комплект. Загрузчиков
драйверов, шрифтов, WebView2, Python, Node.js или библиотек при запуске нет.
Windows, Edge либо IE11 и штатный Windows PowerShell 5.1 должны присутствовать заранее.
HTML-инструкция читается в браузере без Word. Целевые ОС: Windows 10/11 x64 и Server
2019/2022/2025; стендовые Windows-проверки выполняются на 2022/2025. Совместимость
конкретной Windows 7 и её TLS не подтверждена.

Сертификат создаётся локально и действует 365 дней. В последние 30 дней его срока
повторите мастер настройки и выдайте сотрудникам новый комплект. Сертификат
организации меняют с ИТ. В нём нужен DNS SAN localhost для локальной проверки
и SAN сетевого имени/IP для клиентов. Проверку HTTPS и защиту Windows не отключают.

Сохраняются реестр, дерево, копирование этапов, подписи и роли, комментарии, импорт/
экспорт, Гант и печать. Лимит — три сеанса. Выход освобождает место сразу;
при обрыве используется тайм-аут, по умолчанию 120 секунд. Для печати Ганта
выбирается A4/A3, для подчинённости — A4 альбомный.

Собственный постоянный технический журнал не создаётся. В server-data есть временный
running.json для управления процессом; он удаляется после штатной остановки.
Системные журналы Windows и следы браузера сохраняются.

## Технические команды

Параметры находятся в config/server.json. Существующий файл при обновлении сохраняют.
--serve запускает сервер без открытия браузера; --service используется службой.
--check проверяет готовность именно этой папки, --stop завершает ручной запуск через
локальный запрос с ключом из папки данных. Служба управляется через Службы Windows.

Результаты обязательных проверок определяются CI коммита поставки. Перечень —
ПРОВЕРКИ.md. Поставку идентифицирует VERSION.txt. Стенд не заменяет проверку
подключения с реального клиентского ПК в вашей сети.
