# Производственный цикл: сервер и браузер

Серверная поставка запускается на Windows Server 2019/2022/2025 или Windows 10/11 x64.
Результаты стендовых проверок перечислены в ПРОВЕРКИ.md. На ПК сотрудников EXE и
WebView2 не нужны: интерфейс открывается в Edge; для IE11 предусмотрен совместимый
вариант тех же скриптов и компоновки. IE10 и более ранние браузеры не заявлены.
Дата в IE11 вводится как ГГГГ-ММ-ДД. Шрифты и скрипты включены в комплект.

## Первый запуск на сервере

1. Распакуйте ZIP целиком в отдельную папку на локальном диске сервера,
   например C:\ProductionCycleServer. Не используйте путь \\сервер\папка.
2. При переносе существующих проектов сначала закройте старые клиенты, сохраните
   резервную копию shared и выполните импорт, описанный ниже. Пустой сервер до
   импорта не запускайте: он создаёт новую базу.
3. Откройте PowerShell в этой папке и настройте адрес:

       .\scripts\server\Configure-Server.ps1 -Address 10.10.208.24 -Port 8443 -OpenFirewall

   Для изменения брандмауэра нужен запуск от администратора. По умолчанию правило
   допускает только локальную подсеть; для сотрудников из других подсетей ИТ
   указывает точные разрешённые адреса через -RemoteAddresses. Маршрутизация и
   корпоративные правила доступа проверяются отдельно.
4. Запустите production-cycle-server.exe. Окно сервера должно оставаться открытым.
5. Откройте Первичная_настройка.cmd на сервере. При новой базе создайте единственного
   администратора, затем профили сотрудников. После импорта используйте прежние PIN.
6. Проверьте адрес https://10.10.208.24:8443 с отдельного клиентского компьютера.
   Клиентам нужен доступ к порту приложения; доступ к общей папке для работы не нужен.

## HTTPS

При первой подготовке сервер создаёт свой сертификат server.cer и закрытый ключ
в tls. Для штатной работы используйте сертификат вашей организации либо настройте
доверие к server.cer на клиентских ПК. Проверяйте отпечаток сертификата перед
добавлением в доверенные. Закрытый ключ server-key.pem клиентам не передаётся.
Настройки сертификата и ключа задаются в config/server.json.
Адрес открытия должен совпадать с адресом в сертификате. При смене имени/IP нужен
соответствующий сертификат; существующий ключ автоматически не заменяется.

IE11 использует TLS Windows. На старых ОС могут потребоваться разрешённый TLS 1.2
и обновления SChannel. Поддержка конкретной Windows 7 и её набора шифров не подтверждена.
Совместимая ES5-сборка интерфейса сама по себе не обновляет TLS или защиту старой ОС.
Режим HTTP для изолированной доверенной сети включается явно: tls=false,
allowInsecureLan=true, listen/publicUrl с http и одинаковым портом. PIN в таком
режиме не шифруется при передаче. По умолчанию сетевой доступ использует HTTPS.

## Постоянная работа

После успешной проверки закройте окно ручного сервера. В PowerShell от администратора:

    .\scripts\server\Install-Service.ps1

Служба ProductionCycleServer запускается от LocalService, автоматически при загрузке
Windows, независимо от RDP. Скрипт ограничивает доступ к папкам данных и TLS службой,
SYSTEM и администраторами. Это настройка только сервера. Удаление службы:

    .\scripts\server\Remove-Service.ps1

Удаление службы не удаляет базу, резервные копии, сертификаты или настройки.
Постоянный собственный технический журнал по умолчанию не создаётся; стандартные
следы служб Windows, браузера и системы сохраняются.

## Перенос существующей базы

До первого запуска сервера, после закрытия старых клиентов:

    .\production-cycle-server.exe --import-database "D:\путь\ProductionCycleNetwork\shared\database\production-cycle.db"

Используйте действующую общую базу, а не случайную локальную копию клиента.
Переносятся проекты, этапы, комментарии, профили, защищённые ключи и подписанный журнал.
Источник не изменяется. Существующая серверная база автоматически не перезаписывается.
Старые файлы черновиков и резервных копий shared этим импортом не переносятся:
сохраните их отдельно; новая версия создаёт свои резервные копии в server-data/backups.
Не работайте одновременно в старой и новой версиях с разными базами.

## Работа сотрудников

Откройте адрес программы в Edge или используйте ярлык Открыть_программу.url,
созданный при настройке. В комплекте также есть Открыть_программу.cmd, который
предпочитает Edge и использует Internet Explorer при отсутствии Edge.
Выберите профиль и введите свой PIN. Реестр, копирование этапов, дерево,
Гант, подписанное сохранение, комментарии, импорт/экспорт и печать работают
через прежние элементы интерфейса. Подтверждение сохранения выбирает профиль сеанса.

Одновременно допускаются три сеанса браузера. При входе администратора четвёртым
последний обычный сеанс получает запрос на сохранение черновика и выход.
Для немедленного освобождения места нажимайте «Выйти». При закрытии вкладки браузер
отправляет уведомление; при обрыве связи место освобождается по тайм-ауту
sessionTimeoutSeconds (по умолчанию 120 секунд).
При потере связи оставьте вкладку открытой до успешного сохранения. Черновик на
сервере не равен подписанному сохранению проекта.

Печать использует браузерный диалог. Для Ганта выберите A4 или A3 соответствующей
кнопкой; для подчинённости используется A4, альбомная ориентация. Проверьте размер
бумаги и ориентацию также в настройках принтера. В IE11 формат бумаги выбирается
в диалоге печати, поскольку поддержка CSS @page ограничена движком.

## Обновление и восстановление

Закройте сеансы и остановите службу. Скопируйте server-data, config и tls в безопасное
место. Обновите EXE, frontend и скрипты из ZIP, сохранив рабочие server-data/config/tls.
Запустите службу, проверьте вход и существующий проект. Изменения схемы базы проходят
существующие миграции; резервная копия создаётся перед миграцией.
