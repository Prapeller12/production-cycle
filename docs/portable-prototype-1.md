# Автономная поставка: прототип №1

## Состав

- app/backend/production-cycle.exe — Rust/Tauri-host со статически связанным CRT;
- frontend — отдельные локальные HTML, JavaScript и CSS;
- runtime/webview2 — Microsoft Fixed WebView2 152.0.4191.62 x64;
- config — пути и описание выбранного runtime;
- data — рабочие JSON;
- exports — TXT;
- temp — профиль WebView2 и временные файлы процесса;
- start.cmd — запуск после распаковки;
- docs — документация и ограничения.

Runtime загружается только на машине сборки. На пользовательском компьютере загрузка или установка зависимостей не выполняется.
Источники: [Microsoft download](https://developer.microsoft.com/en-us/microsoft-edge/webview2),
[Fixed Runtime distribution](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).

## Запуск

1. Полностью распаковать ZIP в локальную папку, доступную текущему пользователю для записи.
2. Запустить start.cmd. Не запускать программу прямо из окна архива.
3. Рабочий JSON сохраняется в data; открывать его можно кнопкой «Открыть проект».
4. Для PDF выбрать в локальном диалоге печати PDF-принтер и папку программы.

Файл EXE без остальных папок не является полной поставкой. UNC/сетевой путь не поддерживается Fixed Runtime.

## Права и следы

При запуске EXE предоставляет группам AppContainer только чтение/выполнение папки runtime/webview2,
как требует Microsoft для Fixed Runtime начиная с версии 120 на Windows 10.
Программа не запрашивает повышение прав: если пользователь не владеет папкой и не может настроить её ACL,
запуск завершается ошибкой. Реестр, службы, автозапуск и системные политики не меняются.

Технические журналы приложения по умолчанию не создаются. Профиль WebView2 остаётся в temp/webview2
и переносится вместе с программой. Автоматического удаления системных журналов или следов Defender нет.
Печать, файловая система и сама ОС могут оставлять собственные следы.

## Контроль сборки

Сборочный сценарий проверяет полный размер CAB, извлечение, версию и Authenticode-подпись Microsoft.
SHA-256 CAB и сведения о подписи записываются в runtime/webview2/RUNTIME-PROVENANCE.json.
Для итогового ZIP создаётся файл SHA-256. В ZIP включается чистая папка приложения до self-test;
тестовые JSON и профиль, созданные проверкой, в распространяемый архив не попадают.

Сценарий --smoke-test используется только для проверки на машине сборки.
Он создаёт temp/self-test.json, тестовый JSON и два TXT, затем завершает процесс.
Обычный запуск не включает этот режим и не создаёт тестовый отчёт.

## Граница готовности

Это native-поставка первого макета с JSON. SQLite, перенос доменной логики в Rust и интеграция с Реестром
не входят в данный этап и не считаются реализованными.
GitHub Windows runner не является чистой пользовательской Windows 10/11.
Даже успешный self-test не заменяет матрицу docs/windows-acceptance.md.
