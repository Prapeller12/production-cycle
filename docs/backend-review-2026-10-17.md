## Что означает счётчик

Счётчик показывает занятые сетевые места, максимум три. Это количество
активных сеансов, а не число зарегистрированных профилей или уникальных ФИО.
При выходе одного клиента освобождается только его место. Наличие других
работающих клиентов сохраняет ненулевое значение. Источник количества —
блокировки слотов; оставшиеся после аварии JSON не увеличивают счётчик.

Добавлена кнопка «Выйти из сеанса». Сначала подтверждается сохранение
черновика в общей папке либо локальной очереди, затем освобождается место,
очищаются PIN и рабочая форма, появляется окно входа. При ошибке сохранения
выход отменяется. Нельзя выйти посередине подписанного сохранения. Ожидание
входа тоже обновляет счётчик; запросы опроса не накладываются друг на друга.

Очередь восстановления находится вне версионного кэша и разделена по
общей рабочей папке. Замена версии не удаляет `network-pending` и
`network-unsent`. Прежние очереди без достоверной идентификации исходной
папки сохраняются в `legacy/<version>` для ручной проверки; автоматически
применять их к выбранной базе нельзя.

Проверки интерфейса находятся в [browser.cjs](../tests/browser.cjs), native
IPC и настоящего EXE — в [network-native-smoke.js](../tests/network-native-smoke.js).

## Терминология и совместимость

| Назначение | Термин интерфейса |
|---|---|
| Проект верхнего уровня | Основной проект |
| Вышестоящий этап | Головной этап |
| Этап следующего уровня | Зависимый этап |
| Структура дерева | Структура подчинённости |

Эти обозначения уже внесены в сетевую ветку до базового коммита проверки;
они проверены в форме этапа, отчёте, структуре и отображении старого журнала.
Актуальная вводная инструкция README приведена к тем же обозначениям.
Пользовательские наименования организаций, включая «Дочерние кампании»,
не преобразуются. Такая системная подпись в исходном интерфейсе не найдена.

Внутренние поля `parentUid`, форматы JSON/TXT и байты исторических
подписанных событий сохранены. Старые заголовки журнала переводятся только
при отображении. `baseRevision` не входит в исторический хеш подписи и не
попадает в переносимый JSON проекта. Для записи существующего проекта
старым клиентом без ревизии будет получен отказ: обновлять нужно все клиенты.

## Проверка и пределы результата

- Локально: `node --test tests/domain.test.cjs` — 39/39; синтаксические
  проверки изменённых JS; `git diff --check`.
- Rust, браузерные сценарии и собранный Windows EXE проверяются workflow
  [production-cycle-network.yml](../.github/workflows/production-cycle-network.yml).
  Локально Rust отсутствует; загрузка Chromium вернула неполный архив.
- Native workflow включает настоящий loopback SMB, первый запуск,
  повторный вход, два клиента одного Windows-профиля, штатное закрытие,
  принудительное завершение и переходы счётчика 1 → 2 → 1.
- Итоговые ссылки на CI и его результат добавляются в описание PR после
  завершения. До успешного выполнения новый бинарный выпуск не подтверждён.

SMB остаётся границей доверия: сотрудник с прямой записью в `shared` может
заменять файлы вне интерфейса. Проверка подписей обнаруживает описанные
частичные подмены, но не доказывает невозможность полной согласованной
замены БД и профилей или отката всей папки. Для этого нужны независимые
контрольные точки/резервирование с отдельными правами либо серверная
авторизация. Дистрибутив, frontend, runtime и config должны быть доступны
сотрудникам только на чтение; разрешения на `shared` задаются отдельно.
Основание: [утверждённая сетевая концепция](network-share-multiuser-concept.md).

Проверка UUID и слота не является доказательством сохранности SMB lease
при любом варианте обрыва сети. На рабочей инфраструктуре дополнительно
нужно проверить три ПК, разрыв связи во время публикации, RDP и Windows
Server 2019/Windows 10/11. Loopback SMB этих условий не воспроизводит.

Рекомендуемый порядок внедрения: резервная копия `shared`, закрытие всех
клиентов, тестовая новая папка с копией данных, приёмка трёх рабочих мест,
затем одновременное обновление всех клиентов. Неподтверждённые локальные
копии восстановления не публиковать поверх общей БД автоматически.
