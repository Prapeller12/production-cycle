ПРОИЗВОДСТВЕННЫЙ ЦИКЛ — ОБМЕН БАЗАМИ
Распакуйте ZIP целиком. Для общей папки используйте production-cycle.exe или прежний сетевой ярлык на этот EXE. Для компьютера без сети распакуйте комплект в свою отдельную локальную папку и запустите OFFLINE.cmd. Данные двух рабочих мест храните раздельно.

До переноса действующих данных закройте все старые клиенты и сделайте проверенную автономную резервную копию. Обновляйте программу в отдельном каталоге. На сервере перенесите копию прежней папки shared в новый комплект при остановленных клиентах. Откройте обновлённый EXE сначала одним сотрудником. Проверяйте число проектов и возможность открытия. Не смешивайте версии EXE для одной общей базы.
При первом открытии укажите новую фразу ХРАНИЛИЩА из 12 и более символов и сохраните её в защищённом месте. Для существующего зашифрованного хранилища нужна прежняя фраза. Всем допущенным к одной общей базе сообщается одна фраза. Затем каждый входит под своим собственным профилем с личным ПИН. Утраченную фразу программа восстановить не может.

ЕЩЁ → ЭКСПОРТ/ИМПОРТ
1. На подключённом компьютере выберите «Экспортировать базу», тип «Проекты для работы без связи». Отметьте проекты. Введите отдельную фразу для файла и личный ПИН. На экране появится полный путь к файлу .pcdb в exports. Передайте файл согласованным способом, фразу — отдельно.
2. На автономном компьютере выберите «Импортировать базу». Укажите файл и его фразу. Нажмите «Распознать файл». Для нового проекта выберите «Создать самостоятельный проект». При первой встрече с ключом сверьте отпечаток с отправителем по отдельному доверенному каналу. Нажмите «Проверить изменения», затем введите ПИН, комментарий и нажмите «Подписать и применить».
3. Сохраняйте свои изменения обычной кнопкой подписанного сохранения. Когда закончите, экспортируйте тип «Изменения автономного компьютера».
4. На подключённом компьютере примите файл аналогичным способом. Независимые изменения обрабатываются отдельно. Спорный срок останется в блоке «Изменения на согласовании». Там видны действующее и предложенное значения. Для действий с закрытыми этапами и статусами используйте обычный подписанный порядок.
5. Чтобы вернуть ответ, экспортируйте «Квитанция и актуальные проекты». На автономном компьютере примите её через ту же кнопку. Повторно переданный неизменённый файл не должен дублировать принятые записи.
6. Если на независимом компьютере уже есть данные в старой программе, возьмите её согласованную резервную .db. При первом импорте сравните названия, предприятия, номера заказов и этапы, укажите назначение каждой карточки вручную. При объединении со старой базой для каждого этапа укажите этап общей базы или выберите «Создать новый этап». Сходство номеров само по себе не объединяет проекты. Обычные пользователи, проверяющие и администратор могут подписывать обмен под своими профилями.

Шифрование защищает чтение файлов без фразы. Сохраняйте отдельную автономную копию, недоступную для записи обычным пользователям; это важно при заражении компьютера шифровальщиком. Полный перечень ограничений — database-encryption.json.

КОПИЯ НА СЛУЧАЙ ШИФРОВАЛЬЩИКА
В программе откройте администрирование и создайте резервную копию всей базы. Запустите ARCHIVE-BACKUP.cmd из корня комплекта. Выберите эту копию, затем папку на отдельном носителе. Утилита создаст новый каталог, проверит совпадение SHA-256 исходного и записанного файла и сохранит SHA256.txt. После сообщения «Архив проверен» отключите носитель. На проверочном рабочем месте поместите архивную .db в папку штатных резервных копий и проверьте восстановление с исходной фразой. Компьютер, имеющий право записи в архив, может повредить его до отключения носителя. Если политика Windows блокирует сценарии, ответственное лицо может штатно скопировать тот же файл на отдельный носитель и сверить обе суммы командой Get-FileHash.
