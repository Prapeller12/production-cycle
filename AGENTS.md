# Разработка программы Производственный цикл

Целевой репозиторий — Prapeller12/production-cycle. Prapeller12/otchet не является
целевым remote. Источник требований — прямые решения владельца и актуальный паспорт
docs/ProductionCycle_Project_Passport_2026-11-14.txt.

## Текущее решение после отката

- Рабочая архитектура — нативное окно EXE, Rust/Tauri 2, HTML/CSS/JavaScript и SQLite.
  Не переводить действующий frontend на React/Vite без отдельного решения владельца.
- Текущий общий комплект открывается ярлыком EXE из общей папки. EXE, Fixed WebView2,
  профиль, рабочая SQLite и временные файлы запускаются только на локальном диске.
- На сервере нет собственного координирующего процесса приложения. Общие снимки,
  блокировки и максимум три сеанса обслуживаются через SMB. Открывать SQLite напрямую
  по SMB запрещено. Протокол: docs/network-share-multiuser-concept.md.
- Самостоятельная локальная поставка хранит данные внутри своей папки и не объединяет
  независимые базы разных компьютеров. Не смешивать её инструкцию с общим режимом.
- Серверная браузерная попытка 06.11.2026 и IE-совместимость являются историей.
  После неё владелец потребовал возврат к EXE с сохранением накопленных функций.
  Не использовать старый server-пакет как текущую архитектуру без нового прямого решения.
- Импортер Excel и настройки подсказок в server/src подключаются нативным кодом как
  общие модули; имя каталога не означает запуск HTTP-сервера.

## Сохраняемые требования

- Автономный ZIP для Windows 10/11 x64, EXE в корне, без установки и штатного повышения прав.
- Runtime, frontend, config и пользовательские данные — отдельные папки.
- Без CDN, телеметрии и собственных технических логов по умолчанию. Явная диагностика
  допускается; деловой журнал и резервные копии — часть функций программы.
- Не обещать отсутствие следов Windows и не удалять системные журналы.
- Сохранять утверждённую компоновку, обязательные поля, дерево, реестр, поиск проектов
  на главном экране, копирование этапов и печать A3/A4/PDF.
- Сохранять утверждённый Excel и образец для всех пользователей, подсказки по первому
  входу профиля и отдельный административный интерфейс.
- Не хранить служебные метки в поле «Ссылка», не использовать LINK для производственного
  дерева, не угадывать ручные статусы из TXT. Открытые вопросы фиксировать явно.
- Изменения базы требуют подписанного сохранения с персональным PIN и комментарием.
  Фактические права ролей проверять в backend; не подменять их скрытием кнопки в UI.
- Доменные правила, константы, UI и файловые адаптеры держать отдельно.
- Не коммитить runtime, рабочую БД, экспорты, профили, секреты и пользовательские файлы.
  Паспорт и технические инструкции проекта допускаются в docs.

## Проверки и выпуск

- Перед коммитом: node --test tests/domain.test.cjs и git diff --check.
- Перед новым выпуском: Rust-сборка с custom-protocol,local-desktop, реальные сценарии
  окна Tauri/WebView2, Excel, PDF без пустых страниц и docs/windows-acceptance.md.
- Для общей папки проверять настоящие SMB/UNC, ярлык .lnk, обычную Windows-учётную запись,
  локальность runtime/профиля/SQLite, сохранение, освобождение сеанса и восстановление.
- При любых исторических IE-доработках не выдавать разбор ES5 или Chromium за проверку IE.
- Проверку CI на Server 2022/2025 не объявлять проверкой компьютера владельца, Server 2019,
  чистых Windows 10/11 или его физического принтера.
- Сведения о выданном ZIP, SHA256 и исходниках закреплены в docs/current-release.json.
  Старый проверенный ZIP не переименовывать в новую сборку и не менять его контрольную сумму.
