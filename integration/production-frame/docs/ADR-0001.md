# ADR-0001. Общая автономная оболочка

Дата: 12.09.2026. Статус: ACCEPTED в пределах прямого запроса владельца
на отдельный фрейм; производственная приёмка Windows остаётся OPEN.

## Основание и границы

Пользователь поручил объединить otchet и production-cycle в одном окне,
сохранив требования и документацию обеих программ. Это разрешение относится
к внешней оболочке, а не к замене технологий, форм или объединению баз данных.

Исследованы исходники otchet eeb540c88bd989aa09bb34899c3d7eab7ce3886a
и production-cycle b8a7e346e0dc83fc295698e4fa56e81b647a0ee5.
Состав фактически включённых бинарных сборок фиксируется отдельно в manifest.json.

## Решение

Отдельный Win32 C++ EXE со статически связанным CRT управляет двумя родными
окнами приложений. Каждое приложение работает в своём процессе и своей
полной portable-папке. Смена раздела скрывает окно, не выгружая приложение.
Фрейм не читает и не изменяет SQLite, не реализует производственные расчёты
и не перехватывает IPC PyWebView/Tauri.

Это не PyInstaller onefile: EXE содержит только фрейм. Frontend, backend,
Python и Fixed WebView2 остаются в отдельных каталогах исходных поставок.
Новый C++ слой не заменяет утверждённый стек ни одного приложения.

## Почему не HTML iframe

У приложений разные native IPC и обработчики файлов/печати.
Открытие HTML в обычном iframe не сохраняет эти механизмы. В частности,
production-cycle использует собственный протокол и Tauri invoke.

## Встраивание и DPI

Применяется Windows SetParent, со сменой WS_POPUP/WS_CHILD, обновлением
рамки, геометрии и UI state. Встраивается только главное окно процесса,
запущенного самим фреймом; другие экземпляры не захватываются.
Контейнер создаётся в DPI-контексте конкретного окна. Для mixed DPI нужен
Windows 10 версии 1803 или новее; Windows 11 входит в целевую матрицу.
Неизвестная версия/недоступность API вызывает явную ошибку.

## Жизненный цикл

Запуск ленивый. Закрытие общее, с предупреждением сохранить работу.
Приложения получают штатный WM_CLOSE по очереди. Отказ/задержка закрытия
не приводит к принудительному завершению. Фрейм остаётся открытым.
Не применяется TerminateProcess, taskkill, инъекция кода или kill-on-close job.
При ошибке встраивания родное окно остаётся доступным пользователю.
Диалоги импорта/экспорта/печати остаются отдельными модальными окнами.

## Риски и неотменённые ограничения

SetParent между разными framework-процессами требует проверки фокуса,
клавиатуры, DPI, диалогов и печати. Успешная компиляция этого не доказывает.
Аварийное завершение оболочки не заменяет сохранение пользовательских данных.
Несохранённое состояние не доступно фрейму через стабильный API; перед
выходом пользователь сохраняет работу штатными кнопками каждого приложения.
Запрет изменения ACL в otchet и существующее изменение RX ACL внутри
production-cycle сохраняются каждый в своей папке. Ограничение otchet
ADR-0001 для чистой Windows 10 не объявляется устранённым.

## Откат

Закрыть фрейм штатно. Запустить каждый исходный EXE из modules отдельно.
Базы и форматы не менялись, обратная миграция не требуется.
