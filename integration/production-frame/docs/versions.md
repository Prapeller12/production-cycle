# Самостоятельная смена версий

1. Скачайте полный автономный ZIP нужной программы из её репозитория.
2. Распакуйте его в **новую отдельную папку внутри ProductionFrame**, например
   `versions/otchet-dev21/ReportingSystem` или `versions/cycle-september/ProductionCycle`.
   Не распаковывайте поверх действующей версии. Все файлы ZIP, включая runtime,
   должны остаться вместе. Один EXE без остальных файлов не подходит.
3. В общем окне выберите раздел, который хотите обновить, и сохраните работу.
4. В меню **Версии → Подключить другую версию выбранного раздела** закройте раздел.
   После его закрытия повторите эту команду и выберите основной EXE из новой папки.
5. Проверьте путь и подтвердите подключение. Нажмите **Открыть раздел**.

Меню **Текущая версия и папка данных** показывает действующий путь.
Оболочка определяет поставку по выбранной папке: номер версии из имени папки
не считается проверенной метаданной. Версию самой программы проверяйте в её интерфейсе.

## Данные и возврат

Каждая версия работает со своей папкой данных. Подключение чистой поставки
откроет её пустую базу — предыдущие проекты остаются в прежней папке.
Автоматического переноса и обратной миграции SQLite нет.
Для продолжения на имеющихся данных используйте штатный перенос/импорт программы
и копию данных, предварительно закрыв все её экземпляры. Совместимость формата
новой и старой версии должна быть проверена средствами соответствующей программы.
Не копируйте единственный файл SQLite из работающего приложения.

**Версии → Вернуться к предыдущей версии** переключает путь обратно после
закрытия раздела. Это возврат к старой папке и её данным, а не перенос новых записей.
Оболочка ничего не удаляет; прежние версии можно хранить для последующего выбора.
Запомнена одна предыдущая версия; остальные доступны через выбор EXE.

## Проверки и границы

Проверяются имя основного EXE, формат Windows x64, наличие встроенного WebView2
и точки входа frontend. Относительный путь должен оставаться внутри оболочки,
в том числе после разрешения ссылок файловой системы. Это проверка состава,
не сертификат подлинности и не доказательство совместимости нового интерфейса.
Используйте доверенные сборки двух исходных программ с прежними заголовками окон.

Замена пути записывается через промежуточный INI и атомарную замену файла.
Базы и файлы модулей не меняются. При отсутствующем модуле оболочка остаётся
доступна для выбора исправной версии. Не запускайте одну папку приложения
одновременно отдельно и через оболочку.

## Обновление самой оболочки

Закройте общее окно. Из пакета Frame-updater замените только ProductionFrame.exe
в корне существующей папки. Дополнительно можно скопировать документацию.
Ваш config/frame.ini, modules и данные заменять не нужно.
