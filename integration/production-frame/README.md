# Производственный контур: общая оболочка v0.1

Предварительная интеграционная версия для двух автономных программ.
Состав, результаты выполненных проверок и незавершённая приёмка описаны
в `docs/verification.md` и `manifest.json` готовой сборки.

## Запуск

1. Полностью распакуйте общий ZIP в новую локальную папку, доступную для записи.
   Если поставка выдана двумя частями `ProductionFrame-01.zip` и `ProductionFrame-02.zip`,
   распакуйте **обе в одну и ту же папку**, чтобы их каталог `ProductionFrame` объединился.
   Отдельный запуск двух частей не предусмотрен.
2. Запустите `ProductionFrame.exe` в корне.
3. Переключайтесь кнопками «Производственная отчётность» и «Производственный цикл».
   Раздел запускается при первом открытии. Повторное переключение сохраняет его
   открытый экран и введённые, ещё не сохранённые данные в памяти.
4. Сохраняйте изменения штатными кнопками каждого раздела.
5. Перед закрытием общего окна сохраните оба раздела. Подтвердите завершение.
   Если программа оставила диалог открытым, завершите его и повторите закрытие.

Установка, права администратора, отдельные Python/Node/WebView2 не нужны по
структуре поставки: полные runtime находятся в папках модулей.
Цель — Windows 10 x64 1803+ и Windows 11 x64. Реальная приёмка чистых ОС обязательна.
Ограничение WebView2 ACL отчётности на Windows 10 сохраняется — см. ADR.

## Данные

Оболочка объединяет рабочие окна. Общая БД и обмен производственными данными
между программами в эту версию не входят: соответствующий контракт не задан.

- `modules/ReportingSystem/data` — данные отчётности; рядом её resources,
  attachments, config, backups, imports, exports, temp и runtime.
- `modules/ProductionCycle/data` — проекты цикла; рядом его frontend, config,
  exports, temp и runtime.
- `config/frame.ini` — относительные пути EXE и префиксы заголовков окон.
  Формат UTF-16 LE, читается стандартным Windows INI API.

Рабочие файлы пользователя в распространяемый архив не включаются.
Для первого испытания используйте копии данных. При переносе закройте обе
старые программы и перенесите полную копию их portable-папок в соответствующие
каталоги `modules`. Не смешивайте файлы разных версий и не копируйте только
основной SQLite-файл из работающей программы. Сначала сохраните исходную копию.

## Возможные ситуации

- Раздел закрыт: нажмите «Открыть раздел».
- Встраивание не выполнено: текст ошибки содержит причину. Родное окно программы
  остаётся доступным для сохранения. Это не успешная работа общего фрейма.
- При переключении открыт диалог сохранения/печати: сначала завершите диалог.
- При запуске может кратко появиться родное окно до присоединения к фрейму.
- Печать, выбор файлов и подтверждения остаются штатными всплывающими диалогами.
- Фрейм не создаёт технические логи, не устанавливает службы, не обращается
  к сети и не меняет системные настройки. Системные следы Windows не исключены.

## Отдельный запуск и откат

После штатного закрытия фрейма можно запускать исходные EXE внутри `modules`.
Перенос базы между форматами и обратная миграция не требуются.

## Для разработчика

Исходники находятся в `src`, настройки в `config`, сборка и проверки в `scripts`.
Сборка выполняется на Windows с MSVC: `scripts/build.ps1 -Output ./dist/frame`.
Внутренний режим `--self-test` проверяет фрейм на двух тестовых процессах с
разными DPI. `--verify-windows` открывает настоящие модули; применять только
на чистой тестовой копии, поскольку этот режим автоматически закрывает окна.
Оба режима записывают явные проверочные материалы в `temp`. Обычный запуск — нет.
