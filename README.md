# Производственный цикл — первый макет

Основание: предоставленный index.html v8 и [архитектура v0.2](docs/architecture-v0.2.md).
Статус: первая self-test версия native host с подключённым Rust/SQLite backend.

Текущая тестовая доработка добавляет список всех SQLite-проектов, импорт пары штатных TXT,
фильтр выполненных этапов, более явное отображение родителя и отдельную диаграмму Ганта.
Схема подчинённости сохранена в реестре и может быть свёрнута. Диаграмма переключается между
подневным, понедельным и помесячным масштабом и печатается отдельно в A4 или A3 landscape.

## Посмотреть макет

Откройте `frontend/index.html`. Интернет и сервер не нужны. Для этого способа требуется уже имеющийся современный браузер.
Нажмите «Демо» либо заполните проект. Создавайте и редактируйте этапы, меняйте родителя,
проверяйте данные, сохраняйте рабочий JSON, формируйте TXT и печатную форму PDF.
В браузере скачивание не подтверждает фактическую запись файла: проверьте сохранённый JSON перед закрытием.

## Структура

| Каталог | Назначение |
|---|---|
| frontend/config | Заголовки TXT, статусы, порог 7 дней, версии JSON |
| frontend/domain | Дерево, проверка, даты, KPI, риски |
| frontend/services | Рабочий JSON и контракт пары TXT |
| frontend/ui | Формы, таблица, визуальное дерево, печатный шаблон |
| frontend/styles | Экранные, адаптивные и печатные стили |
| src-tauri/src/commands | Локальные команды сохранения и печати |
| src-tauri/src/infrastructure | Portable-пути и запись файлов |
| config | Расположение runtime, данных и ресурсов |
| scripts | Сборка полного ZIP из EXE и Fixed Runtime |
| tests | Проверки дерева, импорта JSON, TXT и отчёта |
| docs | Исходная архитектура, решения и приёмка Windows |

В native host интерфейс загружается из отдельной папки frontend; приложение не использует localhost-сервер.
Проекты сохраняются транзакционно в `data/production-cycle.db`, TXT — в `exports`. TXT-файлы имеют BOM.
Кнопка «Все проекты» показывает сохранённые заказы из SQLite с их сроками и процентом выполнения. При открытии HTML в обычном браузере сохраняется fallback на переносимый JSON.
Импорт пары TXT сначала проверяет оба файла и дерево, затем переносит данные в рабочее поле и сохраняет проект. Поскольку TXT не содержит ручных статусов, импортированные этапы получают статус «Не начато».
Экранный фильтр по умолчанию скрывает выполненные этапы, но не изменяет данные: TXT, SQLite и PDF используют полный проект, а процент выполнения в PDF считается по всем этапам.
Импорт JSON в браузерном fallback не заменяет текущий проект до полной проверки и подтверждения замены.
Экспорт не перезаписывает существующие файлы. Runtime WebView2 и его профиль размещены рядом с программой. Для runtime приложение настраивает только
права чтения/выполнения AppContainer на его папку согласно требованиям Microsoft.
Путь определяется от EXE, а не от текущей рабочей папки.

## Проверки разработчика

```sh
node --test tests/domain.test.cjs
cargo test --manifest-path src-tauri/Cargo.toml
cargo build --release --features custom-protocol --manifest-path src-tauri/Cargo.toml
```

Для визуальных проверок (только машина разработчика): Playwright и Chromium;
`PLAYWRIGHT_MODULE` может указывать на установленный пакет Playwright.

```sh
node tests/browser.cjs
```

Сборка Rust выполняется на Windows с инструментами Rust/MSVC/Windows SDK. Эти инструменты не нужны конечному пользователю.
Workflow `Production cycle prototype checks` проверяет код, подпись Fixed WebView2, собирает полный ZIP
и запускает native self-test из распакованной копии с кириллицей и пробелами в пути.
Артефакт `ProductionCycle-prototype-1-windows-x64` появляется только после успешной проверки.
Подробности: [автономная поставка](docs/portable-prototype-1.md).

Полный ZIP формируется на Windows после подготовки Microsoft Fixed WebView2 x64:

```powershell
./scripts/package-windows.ps1 -FixedRuntimePath C:\Build\WebView2Fixed -OutputPath C:\Build\Prototype1
```

Распакуйте полный ZIP в локальную доступную для записи папку и запустите `start.cmd`.
Установщик, права администратора, системный Python/Node и установку WebView2 программа не запрашивает.
Если bundled runtime отсутствует, запуск прекращается с сообщением.

## Ограничения первого макета

- Целевые системы: Windows 10/11 x64. Приёмка на чистых ОС ещё обязательна; 32-битные Windows и ARM64 не заявлены.
- Сборка полного ZIP с Fixed WebView2 выполняется workflow; используйте только артефакт успешного запуска.
- SQLite является рабочим хранилищем native self-test версии; браузерный HTML-режим продолжает использовать переносимый JSON.
- В native-режиме обязательные поля, даты, дерево, TXT-контракт и модель управленческого отчёта проверяются Rust backend через Tauri IPC.
- React/Vite ещё не внедрены; утверждённый интерфейс сохраняется как статический frontend без изменения компоновки.
- Импорт TXT предназначен только для пары файлов производственного цикла и не заменяет обычный импорт корреспонденции Реестра.
- Ручные статусы отсутствуют в TXT и не восстанавливаются из него; импорт задаёт статус «Не начато».
- Статус LINK основной программы не используется. Данные производственной отчётности не меняются.
- Нет собственных debug/access-логов, телеметрии, CDN или фонового обновления.
- Полное отсутствие системных следов не гарантируется. Программа не удаляет журналы Windows или данные защитного ПО.
- Печать идёт через локальный диалог: пользователь должен выбрать сохранение PDF в папку программы.

Источники технических решений: [Tauri: Windows runtime](https://v2.tauri.app/distribute/windows-installer/),
[Tauri: data_directory](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html),
[Microsoft: Fixed Runtime](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).
Следующий этап — завершить portable-поставку и пройти [матрицу Windows](docs/windows-acceptance.md), затем переносить доменную модель в Rust/SQLite.
