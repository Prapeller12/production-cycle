# Производственный цикл

Автономная Windows-программа для проектов, этапов производства, контроля сроков и диаграммы Ганта.
Актуальная архитектура — **отдельное окно EXE со встроенным Fixed WebView2**.
В совместном режиме сотрудники запускают EXE ярлыком из общей папки: исполняемая часть
подготавливается на локальном диске каждого компьютера, общие данные остаются на сервере.
Серверная служба приложения и установленный браузер для этого режима не нужны.

## Запуск и перенос данных

1. Закройте старую программу на всех компьютерах и сохраните копию старой папки.
2. Распакуйте полный комплект в **новую** общую папку сервера.
3. Перенесите данные по [краткой инструкции](docs/native-share-startup.txt):
   прежнюю папку `shared` или `data` целиком либо проверенную резервную копию серверной базы.
4. Создайте новый ярлык на `production-cycle.exe` из нового комплекта. EXE отдельно не переносите.
5. Войдите прежним профилем и PIN, проверьте проекты и журнал, создайте резервную копию.

Первое открытие копирует приложение и runtime в проверенный локальный кэш.
Окно запуска показывает этап подготовки; при отказе — причину, пути и код ОС при наличии.
Основной способ открытия — двойное нажатие EXE. `app/start.cmd` является вспомогательным запускателем.

Участникам нужны чтение и запуск файлов приложения, запись в `shared` и доступная локальная папка.
Право открыть общую папку не означает наличие RDP. Права SMB/NTFS настраиваются отдельно.
Подробности переноса, восстановления и диагностики приведены в паспорте.

## Что включено в текущую программу

- Карточка проекта, несколько проектов в одном заказе, этапы и сворачиваемая подчинённость.
- Реестр, контроль сроков и Гант с масштабами день, неделя, месяц и квартал.
- Строка **«поиск проектов» на главном экране** и прокручиваемый список сохранённых проектов.
- **Копирование этапов** с новым ID и статусом «Не начато», без копирования подтверждения выполнения.
- **Импорт .xlsx** по утверждённому образцу с предпросмотром; подписанное сохранение после импорта.
- **«Ещё» → «Скачать образец отчёта»** для всех пользователей; образец также лежит в `samples` поставки.
- Кнопка экспорта для Реестра только у администратора.
- Правила при первом входе профиля и повторное открытие через **«Ещё» → «Подсказки»**.
- Отдельный интерфейс администратора, пользователи и PIN, журнал «было → стало», проверка подписей.
- Автоматические и ручные резервные копии, защита сохранения по ревизии проекта.
- Печать проекта, структуры и Ганта A3/A4 с исправлениями первой страницы, дат и длинных подписей.
- Подробная нативная диагностика, локальная подготовка WebView2, исправления UNC и сетевого ярлыка.

Текущий backend допускает подписанное завершение этапа всеми тремя ролями, включая проверяющего.
Возврат выполненного этапа в работу, его удаление или смена идентификатора доступны только администратору.
Изменение полномочий проверяющего требует отдельной правки разрешений; при синхронизации Git поведение не менялось.

## Архитектура и автономность

Нативный клиент использует Rust, Tauri 2, SQLite и включённый Fixed WebView2.
Frontend этой сборки состоит из HTML, CSS и JavaScript.
Установленные Python, Node.js, Rust, Edge и отдельная установка WebView2 конечному пользователю не нужны.
Шрифты, значки и образец Excel включены в ZIP; внешние CDN и интернет для работы приложения не используются.
Для печати нужен уже установленный в Windows принтер или PDF-принтер.

При совместной работе SQLite-соединения открываются **локально**.
Снимок `shared/database/production-cycle.db` обновляется через файловые блокировки;
прямое совместное открытие SQLite по SMB не применяется.
Черновики и неподтверждённые изменения сохраняются с возможностью восстановления.
Собственные технические логи по умолчанию отключены; деловой журнал и резервные копии остаются функциями программы.

Существует также самостоятельная локальная поставка с собственной папкой `data`.
Её описание находится в [локальной инструкции](docs/local/Инструкция.txt).
Независимые локальные копии на разных компьютерах имеют отдельные базы.

## История браузерной попытки и отката

В проекте была реализована серверная схема HTTPS с Edge и IE11.
В условиях владельца она сопровождалась проблемами открытия, вёрстки IE, выдачи Excel и печати.
По решению владельца выполнен **откат к нативному EXE с сохранением функциональных изменений**.
Затем исправлен запуск этого клиента через ярлык из общей папки.

Каталоги `server`, `shared-launcher`, старые IE-исправления и серверные инструкции сохранены как история.
Их наличие не означает, что текущая поставка требует браузерный сервер.
Нативный упаковщик исключает старый `frontend/legacy` из рабочего комплекта.

## Работа с исходниками

```sh
node --test tests/domain.test.cjs
git diff --check
cargo test --locked --release --features custom-protocol,local-desktop --manifest-path src-tauri/Cargo.toml
cargo build --locked --release --features custom-protocol,local-desktop --manifest-path src-tauri/Cargo.toml
```

Нативная сборка и упаковка выполняются на Windows с инструментами разработчика.
Для общего комплекта используется `scripts/package-native-share.ps1` и включённый Fixed Runtime.
Автоматическая проверка `main` вызывает полный нативный workflow
`.github/workflows/production-cycle-startup.yml`; старый прототип больше не публикуется автоматически.
Рабочие базы, runtime, секреты и пользовательские файлы в Git не добавляются.
